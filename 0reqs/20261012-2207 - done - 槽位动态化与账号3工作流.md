## 二、讨论要点(四轮质询 + 一个定论)

| 议题 | 结论 |
|------|------|
| workflow name/job id 为何不同 | name 在本项目里被 run 清理过滤逻辑依赖(`github.workflow`);job id 仅文件内唯一,统一无影响 |
| 去掉 name、统一 job id | **可行且零补偿**:无 `name:` 时 `github.workflow` 自动等于文件名(含 .yml,天然唯一),Actions 显示与清理过滤都回退文件名;从此复制文件改文件名即得新工作流 |
| ACCOUNT_INDEX 是否冗余 | 功能上冗余(env 作用域已选账号)但保留——它是**断言**:复制漏改编号时凭据与 INDEX 不匹配会 exit(1) 红叉,而非静默错跑/账号续期悄悄断掉 |
| 凭据为何不叫通用 LUNES_EMAIL | secret 名必须编号(仓库级命名空间);env 名可通用但会让断言失效且丢 run-all 模式,维持编号 env |
| 加账号成本分层 | ①yml+secrets 层是 GitHub 硬约束(secrets 只收字面量键名,不可动态索引,每账号必须有独立 yml);②app.py 层是槽位写死 1/2 的历史包袱,可一次性治好 |
