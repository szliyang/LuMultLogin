## 一、需求

1. **新增节点连通性测试工作流**:单纯用来验证 node link 能否正常访问 Cloudflare 和 `https://betadash.lunes.host/`,不登录、不开浏览器——用于配置/更换 `NODE_LINK1`/`NODE_LINK2` 前筛选节点。
2. **日志 IP 掩码**:续期脚本(app.py)和节点测试脚本的日志暴露了代理真实 IP,要求每段只显示首位数字,最终输出 `1*.2*.3*.4*` 形式,**`*` 号不和位数挂钩**(用户明确约定的格式)。

## 二、讨论/决策要点

| 议题 | 结论 |
|------|------|
| 测试能力边界 | curl 不执行 JS:能判定"IP 是否被 CF 拉黑/挑战、站点是否可达、是否返回真实登录表单",但 Turnstile 交互挑战能否通过只有真实浏览器流程可验证;✅ 是好节点的强信号,不等于 100% 能过盾 |
| CF 判定分级 | 200+登录表单=✅;`cf-mitigated: challenge`/Just a moment=⚠️ 警告不判失败(浏览器可能仍能过);`cf-mitigated: block`/非 200/超时=❌ 判失败 |
| 节点链接输入方式 | `workflow_dispatch` 的 `inputs.node_link` 临时粘贴(留空则测 secrets NODE_LINK1/2);dispatch input 会留在 run 事件记录里(含节点凭据),靠末尾清理步骤只留最近 1 条 + 仓库保持私有缓解 |
| IPv6 掩码 | 同规则按冒号分组:每分组首位字符+固定 `*`,压缩段保持 `::` 结构 |
| 哪些算"代理真实 IP" | 出口 IP(verify_proxy、run_account 的 api.ip.sb、trace 的 ip=)与节点服务器解析 IP(retry_singbox_ipv4 的 A 记录改写、IPv6 字面量警告)全部打码;节点域名保留(分享链接本就含域名) |

## 三、代码变更

### 1. 新增 `.github/workflows/test-node.yml`(20261007-1430)
- **触发**: 仅手动 `workflow_dispatch`,可选输入 `node_link`(支持 vless/vmess/trojan/hysteria2/hy2/tuic/anytls/socks5);留空则依次测 `NODE_LINK1`/`NODE_LINK2` secrets。
- **链路**: 下载 setup_proxy.sh → 按待测节点起 sing-box → 三项探测全部经本地 `127.0.0.1:1081`、带 Chrome UA:
  ① 出口 IP(api.ip.sb)→ ② Cloudflare 边缘(cdn-cgi/trace,输出 loc/colo)→ ③ betadash 登录页(HTTP 状态 + 表单/挑战判定)。
- **工程细节**: 协议白名单预检(不支持协议秒判,不白跑 sing-box);多节点循环前先 `pkill` 防 sing-box 残留串号;任一失败整体 exit 1(红叉);纯 bash 无 checkout/Python 依赖,单次 run 约 2~3 分钟;无 keepalive 步骤(非定时工作流);run 清理只留最近 1 条。

### 2. 日志 IP 掩码(20261007-1504)
- **app.py**: 新增 `mask_ip()`(位于 `mask_email` 旁),替换四处打印——`verify_proxy` 出口 IP、`run_account` 浏览器出口 IP、`retry_singbox_ipv4` 的"强制 IPv4"目标 IP 与 IPv6 字面量警告。非 IP 文本原样透传。
- **test-node.yml**: 内嵌 bash 版 `mask_ip()`(awk 实现,同规则),应用于"出口 IP"输出与 trace 的 `ip=` 行;并加固兜底分支——异常响应时 `echo "$trace"` 改为剔除原始 `ip=` 行后再输出,堵住整段泄漏的边角。
- **README.md**: 测试工作流说明补充掩码格式注记。
