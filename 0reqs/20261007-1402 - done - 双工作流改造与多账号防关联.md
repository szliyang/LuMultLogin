# 双工作流改造与多账号防关联(阶段总结)

- **BUILD_VERSION**: 20261007-1402
- **仓库**: szliyang/LuMultLogin(个人定制仓库,基线 = 上游 fcnllai/LuMultLogin@7fa20c0,另有 `upstream` 分支作纯镜像)
- **状态**: done(代码已完成并通过本地行为测试,待 secrets 迁移 + 提交推送 + dispatch 验证)

## 一、需求

1. 将上游单 workflow「一次 run 内先后登录两个 lunes 账号」的模式,改造为**每账号一个独立 workflow**,消除多账号关联风险。
2. 错开两个账号的续期时间(约 5 天),并错开小时/分钟。
3. 保持将来**同步上游改进**(尤其自动登录逻辑的适应性修复)的便利性——git 结构上采用「`upstream` 分支纯镜像 + `main`(默认分支)承载定制」。
4. 环境变量/secrets 命名统一编号:`ACCOUNT_INDEX=1/2` ↔ `LUNES_EMAIL1/2` ↔ `NODE_LINK1/2`。
5. 配置校验加固:空白凭据按未配置处理;配置不齐时 workflow 显式红叉而非静默空跑。

## 二、讨论要点(决策记录)

| 议题 | 结论 |
|------|------|
| 多协议代理链接为何 Action 能支持 | runner 上装 sing-box 内核,脚本解析分享链接生成配置,浏览器只挂本地 127.0.0.1:1081 HTTP 代理 |
| Secrets 配置位置 | 仓库级 Secrets(Settings → Secrets and variables → Actions),workflow 未用 GitHub Environments,加 `environment:` 声明也无必要 |
| time.txt 自动提交 | 对公开仓库 60 天无活动会禁用 scheduled workflow 的官方机制做仓库保活,不违反 ToS |
| 多账号关联风险 | 上游 7fa20c0 已解决最大项(同 IP:每账号独立节点/独立 sing-box 生命周期);本次改造解决时间窗关联;指纹(同 Chrome 版本/分辨率/时区)留待后续,小站场景下优先级低 |
| 拆分基线选择 | 必须从上游**最新**出发而非旧基线(277ceda),落后基线只会让未来同步 delta 越滚越大 |
| 分支结构 | 用户最初的「main=镜像+定制分支」不可行:**cron 只从默认分支触发**;改为 main(默认)=定制、upstream 分支=镜像,日常 `merge upstream` 吸收改进 |
| Chrome 版本/UA 差异化 | 只改 UA 字符串会造成与 TLS/HTTP2 指纹不一致的反效果;正确做法是 pin 不同的 Chrome for Testing 实版本(未实施,属后续可选) |

## 三、代码变更(全部在 main 工作区,未提交)

### 1. 双工作流改造(20261007-1148)
- **app.py**:
  - 账号条目新增 `slot` 字段(1/2),与「实际配了几个账号」解耦;
  - `main()` 新增 `ACCOUNT_INDEX` 按槽位选账号:"1"/"2" 只跑对应账号,不设置保持单进程跑全部的旧行为;非法值/未配置账号报错退出。
- **新增 `.github/workflows/login-acc1.yml`**:账号1,cron `4 6 2,12,22 * *`(北京 14:04,每月 2/12/22)。
- **新增 `.github/workflows/login-acc2.yml`**:账号2,cron `17 3 7,17,27 * *`(北京 11:17,每月 7/17/27)。
  - 日期错开 5 天、时分错开:消除登录时间相关性 + 避免 time.txt 推送竞争;
  - 各自只传本账号凭据与专属节点,keepalive 与 run 清理步骤两边保留(清理按 workflow 名各自过滤)。
- **删除 `.github/workflows/login.yml`**(防止旧单工作流继续双跑账号)。
- **README.md**:双工作流时间表、secrets 表、说明更新。

### 2. 环境变量编号统一(20261007-1350)
- 凭据:`LUNES_EMAIL1/2`、`LUNES_PASSWORD1/2`(旧命名 `LUNES_EMAIL`/`LUNES_EMAIL1` 弃用)。
- 节点:`NODE_LINK1/2` 与槽位一一对应;`parse_node_links` 改为 `parse_nodes` 返回 `{slot: link}`,**按槽位领取**(只配 NODE_LINK2 时账号1 直连而非错分),删 `assign_node`;
- 兼容回退:两者都没配时仍解析旧多行 `NODE_LINK`(第1行→账号1、第2行→账号2);`NODE_LINK{n}` 误配多行只取第 1 行。
- 两个 workflow 的 env 段与 README 同步更新。

### 3. 配置校验加固(20261007-1355)
- 凭据与 TG 配置读取统一 `.strip()`:secret 误粘空白按「未配置」处理(代价:密码含首尾空格不受支持);
- 三处配置错误(无账号/ACCOUNT_INDEX 非法/选中账号未配置)由静默 `return` 改为 `sys.exit(1)`:workflow 红叉 + GitHub 失败邮件,杜绝静默空跑;连带效果是此类失败会跳过后续 keepalive/清理步骤(可接受)。

### 测试
- `py_compile`、两个 yml YAML 解析通过;
- 桩掉 seleniumbase/requests 后真实导入 app.py 共跑 12+ 场景:双工作流各自形态、按槽位分节点、旧多行回退、多行取首行、空白凭据剔除、三类配置错误 exit 1、正常路径不受影响——全部符合预期。

## 四、遗留事项(用户操作)

1. **secrets 迁移**(破坏性):`LUNES_EMAIL→LUNES_EMAIL1`、`LUNES_PASSWORD→LUNES_PASSWORD1`、`LUNES_EMAIL1→LUNES_EMAIL2`、`LUNES_PASSWORD1→LUNES_PASSWORD2`,新建 `NODE_LINK1`/`NODE_LINK2`(建议出口不同);TG 两项不变。
2. 提交推送 main,两个工作流各 `workflow_dispatch` 手动验证一次再交给 cron。
3. 日常同步上游:`git fetch upstream && push --ff-only 到 upstream 分支 && main 上 merge upstream`(定制集中在两个 yml 与 app.py 小段逻辑,预期冲突面很小)。
4. 可选后续:每账号 pin 不同 Chrome for Testing 版本 + 匹配节点地理的 TZ;app.py 出口 IP 打日志的脱敏(上游遗留)。
